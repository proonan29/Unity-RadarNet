# RadarNet — 레이더 데이터링크 추적 시뮬레이션 (처음부터 만드는 순서)

한반도 주변 **실제 지형 1,000 km × 1,000 km**(바다·육지)에 **가상 레이더 32기**를 자동 배치하고,
드론·헬기·전투기·민항기·순항미사일·탄도미사일이 지나갈 때 **우연히 포착한 레이더가 데이터링크로 항적을 보고하고,
다른 레이더가 그 항적을 이어받아(큐잉·핸드오버) 같은 항적번호(STN)로 계속 추적**하는 과정을 보여 줍니다.
CleanerBot·WeldingBot·ThemePark·WeatherScape와 같은 방식(Unity CLI + Pipeline 패키지, `rn_` 명령, 명령 하나로 씬 재생성)으로 만들었습니다.

- 환경: Windows, Unity 6000.6.3f1 (URP, `com.unity.template.urp-blank`), Unity CLI 1.0.0-beta.11
- 경로: `D:\UnityAIProjs\DigitalTwin\RadarNet`, GitHub: https://github.com/proonan29/Unity-RadarNet (공개)
- 패키지 추가: `com.unity.pipeline` 0.8.0-exp.1 (`[CliCommand]` → `unity command rn_*`)
- 작업 순서: C# 작성 → `AgentTools\dryrun.ps1`(컴파일 확인) → `Refresh.cs` → `rn_*` 명령 → `rn_capture`/`snap.ps1` 스크린샷 → git 커밋
- 처음 만들기
  1. `unity projects create RadarNet --path D:\UnityAIProjs\DigitalTwin --editor-version 6000.6.3f1 --template com.unity.template.urp-blank --no-cloud`
  2. manifest에 `com.unity.pipeline` 추가, WeatherScape의 Noto Sans KR 폰트·테마 복사 → `unity open`
  3. `rn_fetch_terrain` (지형 내려받기·변환) → `rn_setup_scene` (씬 생성)
- 레이더 위치·제원은 **가상**(지형에서 자동 선정)이며 실제 시설과 무관합니다. 비행체 제원도 일반적인 예시 값입니다.

## 4. 추적과 데이터링크
1. **국지 추적**(레이더마다): 예측 위치와 플롯의 마할라노비스 거리로 게이팅(확정 16, 가설 22) → 가까운 순 탐욕적 할당(GNN) → 칼만 갱신. NIS > 9면 기동 모드(q 900), 조용하면 q 15. 스캔을 놓치면 게이트를 넓힘. 탄도(고도 25 km 이상 또는 900 m/s 이상)는 중력항 사용
2. **확정**: 3회 탐지. 확정 순간 STN 결정
   - 같은 레이더의 살아 있는 항적과 겹치면 → 중복이므로 버림
   - 같은 레이더의 놓친 항적(1.2 주기 이상 갱신 없음)과 맞으면 → 그 STN을 넘겨받음(항적 복구)
   - 링크로 받은(또는 자기가 보냈던) 최근 180 s 항적과 위치·속도가 맞으면 → **같은 STN 인수**
   - 없으면 자기 블록에서 새 STN (노드 k → (k+1)·1000 + n, 예: L02 → 02001)
3. **보고**: 확정 항적은 4 s마다 링크로 방송(위치·속도·공분산·TQ·분류). 자기 보고도 기억 → 놓쳤다가 다시 잡아도 같은 번호
4. **큐잉(핸드오버)**: 1 s마다 링크로 받은 항적 중 자기 범위로 들어오는 것(σ < 10 km)을 큐로 만듦. 큐 영역 안은 낮은 문턱(Pfa 1e-4)으로 보고, 첫 플롯에서 바로 확정 + 같은 STN
5. **중복 해소**: 다른 STN과 2 s 간격 3회 연속 상관되면 번호를 바꿈. **먼저 생긴 STN이 남음**(같으면 낮은 번호)
6. **관제소 상황도**: STN별로 최근 9 s 보고를 외삽해 공분산 교차(CI)로 융합. 보고 책임(R2) = TQ 최고(3 이상 차이 + 20 s 유지 조건으로 바뀜, 바뀔 때 핸드오버 기록). 보고가 끊기면 외삽(코스팅), 90 s(탄도 25 s) 후 종료
- 외삽 잡음(q): 민항기 5, 드론·헬기 30, 탄도 40, 순항미사일 300, 그 외 900
- 분류(운동학): 25 km 이상 또는 900 m/s 이상 탄도 / 55 m/s 미만 드론 / 100 m/s 미만 헬기 / 지표 450 m 이하·150 m/s 이상 순항미사일 / 9 km 이상·300 m/s 이하 민항기 / 그 외 제트기

- 순항미사일·헬기(지표 60~120 m)는 지형에 가려 연속성이 낮음 → 갭필러 배치의 필요성을 보여 줌. 180 s 넘게 가려지면 새 번호
- 드론 편대(11 km 간격, L04 한 대만 봄)는 항적 교차·번호 섞임이 생김(실제와 비슷한 한계)
- 탐지 범위(1 m², Pd ≥ 0.5, 1대 이상 / 2대 이상): 지표 100 m 육지 14% / 1%, 바다 40% / 4% · 1 km 육지 68% / 20%, 바다 84% / 33% · 10 km 육지 98% / 78%, 바다 96% / 66%
- 개선 과정(Mixed 2400 s, 물체당 STN): 처음 3.33 → 놓친 항적 기억·자기 보고 저장 2.56 → 등급별 외삽 잡음·180 s 기억 2.00 → 중복 항적 버림·먼저 생긴 번호 유지·스캔 놓치면 게이트 확대 1.56
- 씬 생성 0.6~1.2 s(차폐 표 32기 0.16~0.2 s, 지형 텍스처 2048² 포함), 컴파일 경고 0

## 9. 주의·한계
- Enter Play Mode 옵션(도메인·씬 다시 불러오기 끔)이 켜져 있어, 플레이 전환 때 DontSave 생성물이 사라짐 → `AppController.EnsureBuilt`가 지도·뷰가 없으면 다시 만듦. 시뮬레이션 상태는 편집 모드에서 이어짐
- `rn_*` 명령 기본 시간 제한 30 s → 긴 작업은 `--timeout`. run_script에는 환경 변수가 전달되지 않으므로 진단 인자는 `AgentTools/_*.txt` 파일로
- PowerShell `cd` 후에도 .NET 경로는 바뀌지 않음 → `[IO.File]`에는 절대 경로
- 지상 레이더는 모두 3D(고각 측정)로 단순화, 다중경로·기상 클러터·전자전·IFF·Link-16 시간 슬롯 구조는 모델링하지 않음. 추적기는 GNN(다중 가설 아님)
- 레이더 위치는 지형에서 자동으로 고른 가상 위치이며, 지도 주변국 영역에도 고르게 배치됨
